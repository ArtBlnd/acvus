# functions

An extern receives an acvus function in one of two ways: lent for the call, as a closure parameter written in Rust's own closure bound, or kept past it, as a function value whose type is a Rust function pointer type under `#[fn_type]`. An extern gives acvus no function value, as its result or as a part of one: neither one of its own, a Rust function or a closure, nor one acvus gave it, which is not yet supported. A kept function value is a `Uniform`, which Rust lets cross back, so a declaration whose result holds a function type is refused where it is registered.

## 1. Closure parameters

An author writes a closure parameter as Rust writes one: a `Fn`, `FnMut` or `FnOnce` bound, its arguments' lifetimes stated by elision or by a binder. Its function type and flows are those its signature writes, so a result that borrows an argument borrows that argument (compiler: extern fn §4). Its effect is the declaration's effect variable (variables §1), which the call consumes, since the call runs it (compiler: extern fn §2).

The body receives a Rust closure that calls the acvus function value through the runtime (runtime §2). An argument crosses by its kind: a view as itself, and a `&T` or `&mut T` to one value as a `Ref` or a `Mut`, so `T` is a type variable or a `Uniform`, whose value sits in a place that holds a `Value` (references §2); a result returns as an owned value, a view, a `Ref` or a `Mut`. A `Fn` bound is no excluded trick (boundary §1): an acvus closure is an ordinary lambda, whose body acvus checks and whose handling of a reference its flows state. The closure is the call's alone, and keeping it past the call is refused. Its bound is its function type's: `Fn` is called many times and holds no exclusive loan, since it may be called through shared borrows at once; `FnMut` is called many times, one call at a time, and may hold one; `FnOnce` is called once.

## 2. A function kept past the call

An author names a function type it keeps once, where it writes it, as an alias of a Rust function pointer type marked `#[fn_type(mode)]`: `#[fn_type(ref)] type Pred<'f, T, E: EffectVar> = fn(&T) -> bool`. The macro bounds each type parameter the alias leaves unbounded by `TypeVar`, as it bounds an extern-defined type's (types §1). The signature is a Rust type, its arguments' lifetimes stated by elision or by a binder as a function pointer states them, so Rust resolves it. The mode is how the function is called, declared where its type is named and never read from a type: `ref` calls it through a shared borrow, as a `Fn` is called; `mut` through an exclusive one, as a `FnMut`; `owned` consumes it, as a `FnOnce` (§1). Beside any mode, `async` calls it asynchronously in place, through the same borrow or by value (§3); it adds nothing to the function type, whose suspending is its effect's.

The function crosses as a function value, kept as `Uniform<R, Pred<'f, T, E>>`, and is called through its projection to a Rust closure for a scope, which borrows the function value for that scope alone, or takes it where its mode consumes it. The projection calls it as the mode states: `call_ref` for `ref`, `call_mut` for `mut`, and `call_once`, which consumes it, for `owned`, each within a scope where the function is `async` (§3). Its effect is the alias's `EffectVar` parameter, which the declarations that keep it fill with their own variable, so a function is kept only with a variable to carry its effect (variables §1). `'f`, the loans the function holds, is the alias's first lifetime parameter, so a type that keeps the function declares that it holds them. The runtime contract gives no `'static` handle for it.

## 3. Asynchronous calls

An extern calls an acvus function asynchronously in place: the call runs as the future that awaits it is polled, and nothing runs it apart. A scope takes the callable and its arguments by value, lends them to the call, the callable as its mode states, and gives back with its result what the call did not consume, so the call's flows are plain moves and what the work keeps shows in its declaration. The work a scope starts is given its loans for every loan the scope may make, so a loan from outside the scope, the caller's own or another scope's, fits none of its calls. A future is dropped only between its polls, so dropping the scope, or the call within it, abandons the call where it suspended, where every storage it was lent is whole (compiler: ownership §4), and what the scope holds is released with it: a callable given by value is the call's from then on, and one no call takes is released with the scope. A function called asynchronously crosses as a function value whose alias is marked `async` beside its mode, as in `#[fn_type(ref, async)] type Fetch<'f, T, U, E: EffectVar> = fn(&T) -> U`, a function whose effect may suspend; a closure parameter cannot be one, since a scope takes its callable by value and a closure parameter is only lent.
