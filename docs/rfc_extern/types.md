# types

## 1. Extern-defined types

An extern-defined type (compiler: extern fn §8) is a Rust type its author defines and marks `#[opaque(..)]`, so that what is opaque is written where the type is. A type the author did not define enters wrapped in one: `#[opaque(runtime = R, args(T))] struct Stack<R, T>(Vec<T>, PhantomData<fn() -> R>)`. Its values are held with their type erased, and nothing inside them is read.

The attribute names every parameter: the runtime, which every such type names, its lifetimes, its type arguments, its effect and its identity. The macro bounds each by its role, a type argument by `TypeVar`, the effect by `EffectVar`, the identity by `IdentityVar` and the runtime by `Runtime`, and refuses a parameter the attribute does not name. It adds nothing to the type: a parameter its fields do not use, the runtime where only its type arguments' bounds name it, is refused by Rust, and its author uses it by a marker field. The type carries at most one effect (variables §1; compiler: extern fn §8) and one identity (compiler: types §3), which the declarations that write it fill with their own variables. An identity is a mark Rust never checks against the value it marks, so a type carries only one: with two, nothing would tell which of its values is whose. Values of several storages are carried by its type arguments, whose values it only moves.

## 2. Structural types

A Rust struct with named fields marked `#[derive(Structural)]` is an acvus object, and a Rust enum so marked is an acvus enum: one acvus type to one Rust type. The author of such an enum writes it `repr(u32)`, and the derive refuses it otherwise. Every field is a `Uniform` or a type variable, which the derive bounds by `TypeVar`, so a value of the type is held as its Rust type lays it out, each field a `Value`, and is given, taken back and projected by its kind (runtime §2).

The derive states the type's declaration and its table: each field's name and where the field lies, and for an enum each variant's name and the tag `repr(u32)` stores, the variant's fields lying where a `repr(C)` struct of the tag and those fields has them. The runtime reads and writes a field by its name through the table, so no order of the fields is assumed. A variant's payload is nothing for a unit variant, its field for one unnamed field, the tuple of its fields for several, and the object of its fields for named ones. A value of the type is made by an extern fn, or by the table where a caller coerces a value of its own into the declaration's type (compiler: types §1, §3). Its release is its fields' alone, whoever made it: the derive writes its `Drop`, so its author writes none, and an extern reads its fields in place and never moves one out.

## 3. The two forms

An extern-defined type is written in one of two forms. In the uniform form every type argument is a `Uniform` or a type variable at its root, and the type is unmarked. In the whole native form no `Uniform` and no variable stands anywhere in it, and it is marked `#` (compiler: types §8). Any other form specializes at a type argument, which the compiler rejects, and is refused; a part a type always holds natively is a field of its own definition. The form is read through the types' own kinds, never from syntax, so an alias or a nesting decides nothing.

A declaration in the whole native form is the `#` member of one written uniformly: the same function at the marked type. It names its uniform member and the choice of that member's variables, as an impl names its generic function, states nothing of its own, and shares that member's declaration. Rust confirms that its signature is its uniform member's at that choice, each part written natively, so a uniform member that lends a part of the marked type has no `#` member. Without its uniform member it is refused: a value that passes an unmarked function even once is unmarked from where it is made, as the compiler decides, and its maker is then the uniform member, so no value changes its representation after it is made. The whole native form is not yet supported.
